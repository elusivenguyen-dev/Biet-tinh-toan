# ORGANIZATION MODEL
## Canonical Skill for Designing, Activating, Governing, Measuring, Learning and Evolving Organizations

---

# 1. PURPOSE

This skill is used to model an organization as a complete, governable and executable system rather than as an org chart, a list of departments, or a set of job descriptions.

It converts:

```text
Reality
→ Purpose
→ Strategy
→ Governance
→ Capital
→ Capability
→ Organization
→ Decision
→ Process
→ Execution
→ Evidence
→ Measurement
→ Learning
→ Evolution
→ Continuity
```

into a coherent Organization Model that can be:

- understood;
- diagnosed;
- designed;
- activated;
- governed;
- measured;
- audited;
- improved;
- transferred;
- scaled;
- simulated;
- evolved.

# 4. WHEN TO USE THIS SKILL

Use this skill when the user asks to:

- design a complete organization;
- redesign an existing organization;
- move from founder-led to system-led;
- build an operating model;
- define units, roles and accountability;
- establish decision rights and delegation;
- build a hybrid functional, matrix, network or case-based structure;
- diagnose bottlenecks, conflicts or founder dependency;
- connect strategy to capability, role, process and KPI;
- build organization registers or a master workbook;
- convert organization documents into a knowledge graph;
- create an executable organization runtime;
- prepare for scale, succession, M&A or continuity;
- build OrgOS or an organization digital twin;
- validate whether an organization is coherent, governable and transferable.

Do not use this skill when the request is only:

- drafting one isolated job description;
- drawing a simple org chart without systemic context;
- writing a single SOP;
- creating a generic team list;
- answering a narrow HR administration question.

For narrow requests, use only the relevant module.


## 5.3 Authority Must Match Accountability

```text
Accountability without authority
→ symbolic responsibility

Authority without accountability
→ uncontrolled power
```

## 5.4 Design Must Become Runtime

A valid design object must have:

- owner;
- authority;
- state;
- trigger;
- workflow;
- evidence;
- metric;
- escalation;
- lifecycle;
- version.

## 5.5 Formal and De Facto Organization Must Be Compared

```text
Formal Organization
≠
De Facto Organization
```

The model must identify:

- informal power;
- hidden decision makers;
- bypassed workflows;
- undocumented knowledge;
- shadow incentives;
- trust networks;
- founder dependency;
- actual coordination patterns.

## 5.6 Organization Must Learn and Continue

A complete organization must survive:

- founder absence;
- executive departure;
- operational disruption;
- data loss;
- supplier failure;
- regulatory change;
- growth pressure;
- ownership transition.

# 15. QUALITY GATES

## Gate 1 — Reality Integrity

Verify:

- facts separated from assumptions;
- formal and actual organization compared;
- evidence quality assessed;
- current-state constraints identified;
- hidden dependencies exposed.

## Gate 2 — Strategy Alignment

Trace:

```text
Purpose
→ Strategy
→ Value Stream
→ Capability
→ Decision
→ Role
→ Process
→ KPI
→ Outcome
```

## Gate 3 — Governance Integrity

Verify:

- decision owner exists;
- reserved matters are explicit;
- delegated authority is clear;
- accountability matches authority;
- escalation is defined;
- conflicts of interest are controlled.

## Gate 4 — Organization Coherence

Verify:

- each capability has an owner;
- each role has a purpose;
- duplicate accountability is minimized;
- interfaces have owners;
- workload is feasible;
- management spans are reasonable;
- critical roles have backups.

## Gate 5 — Runtime Readiness

Every active object must have:

- state;
- trigger;
- workflow;
- owner;
- authority;
- evidence;
- metric;
- escalation;
- lifecycle.

## Gate 6 — Evidence and Measurement Integrity

Verify:

- metrics are linked to outcomes;
- evidence source is defined;
- data owner exists;
- thresholds are explicit;
- review cadence exists;
- measures lead to decisions.

## Gate 7 — Risk and Control Integrity

Verify:

- critical failure modes identified;
- preventive and detective controls exist;
- control owners are assigned;
- exceptions are logged;
- residual risk is accepted by authority.

## Gate 8 — Learning and Evolution

Verify:

- lessons are captured;
- design changes are versioned;
- obsolete structures can be retired;
- adaptation decisions are governed;
- learning affects future design.

## Gate 9 — Continuity

Test resilience against:

- founder absence;
- executive departure;
- process interruption;
- system outage;
- data loss;
- supplier failure;
- regulatory change;
- ownership transition.

# 18. FAILURE MODES

## Design Failures

- designing around current people;
- copying another company’s org chart;
- roles without authority;
- authority without accountability;
- capability without owner;
- KPI without outcome;
- structure without interfaces;
- process without evidence;
- succession added too late.

## Runtime Failures

- design not activated;
- workflow bypass;
- undocumented exception;
- missing evidence;
- unauthorized decision;
- weak escalation;
- delayed measurement;
- no design feedback.

## Governance Failures

- founder remains hidden approval node;
- committees exist without decision rights;
- excessive approvals;
- informal veto power;
- policy conflicts;
- delegated authority is reversible by habit.

## Learning Failures

- lessons not recorded;
- same issue recurs;
- no version control;
- retired processes remain active;
- metrics do not change decisions.

## Continuity Failures

- critical knowledge held by one person;
- no successor;
- no backup role;
- no recovery plan;
- customer or supplier relationships are personal assets;
- organizational memory disappears with staff turnover.

# 26. COMPLETION STANDARD

The Organization Model is considered complete only when:

```text
Every strategic outcome
is linked to a capability;

every capability
has an owner;

every owner
has authority;

every decision
has a decision right;

every process
has a workflow;

every workflow
produces evidence;

every outcome
has a measurement;

every risk
has a control;

every critical role
has a successor;

every design change
is governed and versioned.
```

The final objective is not a better chart.

```text
A governed,
executable,
observable,
evidence-driven,
transferable,
adaptive
and continuous organization.
```
