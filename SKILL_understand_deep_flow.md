# SKILL.md — Understand Deep Flow

## 1. Skill Name

**Understand Deep Flow**  
**Năng lực Hiểu Sâu Dòng Chảy**

---

## 2. Purpose

Use this skill to understand, diagnose, measure, redesign, govern and evolve any flow inside a system.

This skill is designed for:

- enterprise systems;
- organizations;
- business models;
- operating models;
- money flow;
- information flow;
- decision flow;
- trust flow;
- power flow;
- capability flow;
- customer flow;
- service flow;
- risk flow;
- learning flow;
- continuity flow;
- family lineage flow;
- consciousness flow;
- universal flow.

The skill does not treat flow as simple movement. It treats flow as the movement of something valuable, risky, scarce, meaningful or controlling through nodes, actors, rules, systems, time and evidence.

Use this skill when the user asks to:

- understand a flow;
- map a flow;
- diagnose a bottleneck;

## 6. Do Not Use This Skill When

Do not use this skill if the user only wants:

- a short definition without analysis;
- a simple translation;
- a generic brainstorming list;
- a purely emotional response;
- a purely legal/medical/financial answer requiring professional advice;
- current facts that must be verified online before analysis.

If the request involves recent facts, law, regulation, market data or company information, verify those facts before applying the flow model.

## 7. First Principles of Flow

### Principle 1 — Flow Always Carries Something

```text
Every flow carries something.
```

A flow may carry:

```text
money,
information,
work,
decision,
authority,
trust,
risk,
knowledge,
attention,
emotion,
memory,
capability,
resource,
obligation,
value,
or continuity.
```

Core question:

```text
What is actually flowing?
```

---

### Principle 2 — Flow Needs a Path

```text
Every flow needs a path.
```

Path includes:

```text
source,
trigger,
channel,
node,
handoff,
interface,
rule,
sequence,
destination.
```

Core question:

```text
Where does the flow start, through which path does it move,
and where should it arrive?
```

---

### Principle 3 — Flow Is Controlled

```text
Every flow is controlled by nodes, rules and controllers.
```

Controllers may be:

```text
formal owner,
actual controller,
decision owner,
approval point,
data holder,
budget owner,
relationship holder,
gatekeeper,
system rule,
informal power center.
```

Core question:

```text
Who or what controls this flow?
```

---

### Principle 4 — Flow Quality Is Damaged by Friction, Leakage, Distortion and Delay

```text
A flow is only as strong as its weakest condition.
```

Main failure modes:

```text
Bottleneck  = blocked flow
Leakage     = lost value
Distortion  = corrupted meaning / information
Delay       = slow movement
Friction    = excess resistance
Fragmentation = broken continuity
```

Core question:

```text
Where is the flow blocked, leaked, distorted or delayed?
```

---

### Principle 5 — Flow Must Learn, Adapt and Continue

```text
A flow that does not learn repeats failure.
A flow that does not adapt becomes obsolete.
A flow that does not continue loses value over time.
```

Core question:

```text
What does this flow learn, adapt, evolve and preserve?
```

## 23. Anti-Patterns

Avoid these mistakes:

```text
1. Treating flow as a vague metaphor.
2. Mapping process without identifying controller.
3. Listing steps without evidence.
4. Measuring activity instead of flow health.
5. Ignoring delay.
6. Ignoring leakage.
7. Ignoring informal power.
8. Assuming official flow equals actual flow.
9. Building dashboard without decision rights.
10. Redesigning process without capability.
11. Creating SOP without learning loop.
12. Scaling a broken flow.
13. Automating distorted flow.
14. Treating continuity as documentation only.
```

## 24. Application Examples

### Example 1 — Money Flow

```text
Carrier: cash / revenue / margin
Path: quotation → contract → collection → receipt → bank → accounting → reconciliation
Controller: finance controller, cashier, case manager
Failures: discount leakage, cash mismatch, delayed reconciliation
Evidence: receipt, bank proof, case revenue file
Metric: cash collection rate, cash variance, reconciliation rate
Redesign: Case ID-based cash reconciliation
```

### Example 2 — Decision Flow

```text
Carrier: authority / approval
Path: issue → evidence → decision owner → approval → action → record
Controller: founder / CEO / delegated owner
Failures: founder bottleneck, no threshold, no decision log
Evidence: decision log, approval record
Metric: decision SLA, delegated decision rate
Redesign: decision catalogue + delegation of authority
```

### Example 3 — Trust Flow

```text
Carrier: trust / confidence / legitimacy
Path: first contact → consultation → promise → delivery → evidence → aftercare
Controller: family advisor, case manager, customer care
Failures: wrong information, price ambiguity, complaint ignored
Evidence: consultation note, signed quote, aftercare record
Metric: trust score, complaint rate, referral rate
Redesign: trust evidence folder + complaint repair protocol
```

### Example 4 — Funeral Case Flow

```text
Carrier: family need / service obligation / dignity / evidence
Path: first call → Case ID → consultation → contract → legal → body care → ceremony → payment → aftercare
Controller: Case Manager
Failures: missing documents, ritual errors, cash mismatch, no aftercare
Evidence: case folder
Metric: case evidence completeness, ritual accuracy, cash reconciliation
Redesign: Hybrid Functional × Case-Based Operating Model
```
