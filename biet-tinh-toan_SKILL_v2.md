---

# 1. Mission

Khi skill được kích hoạt, nhiệm vụ là chuyển một vấn đề phức tạp thành:

```text
Grounded diagnosis
+
Ranked constraints
+
Plausible scenarios
+
Governed recommendation
+
Execution readiness
+
Learning closure
+
Continuity protection
```

Không chỉ mô tả framework. Phải tạo giá trị quyết định cụ thể.

# 2. Activation Rules

## Activate when the user asks to

- biết tính toán toàn cục;
- phân tích chiến lược hoặc quyết định trọng yếu;
- xác định root cause, binding constraint hoặc bottleneck;
- đọc thời, chu kỳ, cục, vị, lực, thế;
- phân tích known, unknown, shadow hoặc de facto reality;
- đọc network, connecting, flow, stock hoặc feedback;
- phân biệt lack, bottleneck, excess và misallocation;
- tính buffer, survival clock, optionality, threshold hoặc transition;
- xây scenario, counterfactual hoặc actor-response analysis;
- lựa chọn giữa nhiều option có trade-off;
- thiết kế decision governance, stage gate, stop rule hoặc rollback;
- phân tích finance, market, organization, transformation, M&A, turnaround, technology hoặc AI bằng mô hình Biết Tính Toán.

## Trigger phrases

```text
biết tính toán
strategic calculation
đọc cục / vị / lực / thế
đọc thời và chu kỳ
unknown / shadow
network / connecting / flow
lack / bottleneck / excess
constraint / buffer / optionality
threshold / transition
scenario / actor response
system calculation
quyết định đúng thời đúng vị đúng mức
```

## Do not use as primary skill when

- user chỉ cần arithmetic đơn giản;
- user chỉ yêu cầu rewrite hoặc translation;
- task là factual lookup không có decision component;
- user yêu cầu một chuyên môn hẹp đã có skill chuyên biệt và không cần strategic synthesis.

Có thể dùng như meta-layer sau khi chuyên môn hẹp đã tạo evidence.

# 3. Non-Negotiable Principles

```text
1. Reality before interpretation.
2. Evidence before confidence.
3. Whole system before local optimization.
4. Constraint before resource expansion.
5. Unknown must remain visible.
6. Shadow reality must be examined without accusation.
7. Timing and position modify action quality.
8. Reversibility must match uncertainty.
9. Influence must carry accountability.
10. Every material decision must produce learning.
11. Continuity is protected through adaptive form, not rigid preservation.
12. Dịch is a change-intelligence layer, never a substitute for evidence.
```

# 4. Operating Mode Selection

Before analysis, classify the task.

## M0 — Orientation

Use when evidence and decision framing are weak.

Deliver:

```text
Decision clarification
Question map
Evidence gaps
Initial hypotheses
Next evidence required
```

## M1 — Minimum Viable Calculation

Use when impact is limited, reversible and short-horizon.

Answer nine questions:

```text
1. Decision?
2. Purpose?
3. Three critical facts?
4. Key unknown?
5. Primary constraint?
6. Main options?
7. Largest downside?
8. Stop / rollback rule?
9. Review date?
```

## M2 — Standard Strategic Calculation

Use for cross-functional or material decisions that can be stage-gated.

Apply the 12-stage runtime, but keep detail proportional.

## M3 — Full Strategic Calculation

Use when the decision is enterprise-wide, high-capital, long-horizon, hard to reverse, legally sensitive, trust-sensitive or continuity-critical.

Apply all 16 layers, hard gates and standard output contract.

## M4 — Survival Calculation

Use when cash, legal standing, operational continuity, trust or another fatal constraint may fail first.

Prioritize:

```text
Fatal constraint
→ Survival clock
→ Mandatory obligations
→ Buffer
→ Containment
→ Optionality
→ Stabilization
→ Restructuring
→ Renewal
```

# 8. Core Calculations

Treat these as heuristics, not universal laws.

## Unknown Exposure

```text
Unknown Exposure
=
Impact
× Unknown Magnitude
× Dependency
× Irreversibility
× Time Sensitivity
÷ Detectability
÷ Buffer
```

## Survival Margin

```text
Survival Margin
=
Available Buffer
-
Expected Stress
```

## Time to Failure

```text
Time to Failure
=
Available Buffer
÷ Rate of Depletion
```

## Optionality

```text
Optionality
=
Number of Viable Options
× Option Quality
× Time Available
× Ability to Execute
```

## Lack

```text
Effective Lack
=
max(0, Required Level - Usable Level)
```

## Bottleneck Pressure

```text
Bottleneck Pressure
=
Demand on Node
÷ Effective Node Capacity
```

## Excess

```text
Excess Load
=
max(0, Input Rate - Absorption Rate)
```

## Fragility

```text
Fragility
=
Dependency
× Concentration
× Irreversibility
× Opacity
× Delay
÷ Buffer
```

## Resilience

```text
Resilience
=
Buffer
× Modularity
× Redundancy
× Adaptability
× Trust
× Learning Speed
```

## Urgency

```text
Urgency
=
Impact
× Rate of Deterioration
× Threshold Proximity
÷ Reversibility
```

## Action Fit

```text
Action Fit
=
Purpose Fit
× Reality Fit
× Timing Fit
× Position Fit
× Configuration Fit
× Network Fit
× Flow Fit
× Constraint Fit
× Capability Fit
× Proportionality
× Reversibility Fit
× Continuity Fit
```

# 9. Decision Rules

## Under high uncertainty

Prefer:

```text
Pilot
Stage gate
Modularity
Small reversible commitment
Buffer
Alternative path
Short review cycle
```

## When Lack exists

Consider:

```text
Acquire
Build
Borrow
Share
Substitute
Simplify demand
Reposition resource
Change standard where legitimate
```

Do not default to adding headcount.

## When a Bottleneck exists

Use:

```text
Protect the bottleneck
Exploit current capacity
Remove non-value load
Improve interface
Move decisions closer
Add targeted capacity
Resequence work
Create an alternative path
Recalculate constraint migration
```

## When Excess exists

Use:

```text
Stop
Reduce
Prune
Consolidate
Reallocate
Standardize
Sequence
Limit WIP
Convert useful slack into buffer
Retire obsolete assets or rules
```

## When survival is threatened

Do not optimize growth. Protect:

```text
Liquidity or critical resource
Mandatory obligations
Operational continuity
Trust
Legal standing
Critical access
Decision speed
Optionality
```

# 10. Quality Gates

A material recommendation is not ready if any relevant gate fails.

```text
G01 Purpose unclear
G02 Boundary undefined
G03 Reality lacks evidence
G04 Assumption presented as fact
G05 Major unknown has no learning or buffer response
G06 Shadow structure not assessed where relevant
G07 Phase and critical clock not identified
G08 Critical flow not traced
G09 Bottleneck not validated
G10 Buffer confused with excess
G11 Actor response not modeled
G12 Irreversible decision lacks scenario test
G13 No accountable decision owner
G14 Owner lacks authority
G15 No stop, rollback or fallback rule
G16 No evidence capture plan
G17 Continuity assets not identified
G18 Legal, ethical or fiduciary boundary violated
```

When a gate fails, state:

```text
Gate failed
Why it matters
What evidence or action is required
Whether a limited reversible step is still permissible
```

# 16. Agent Behavior

## Always

- distinguish fact, inference, assumption and unknown;
- identify the primary constraint;
- rank findings by materiality;
- state confidence and revision triggers;
- distinguish formal, de facto and shadow reality;
- model timing, delay and critical clocks;
- consider actor adaptation;
- include second-order effects;
- preserve optionality under uncertainty;
- specify owner, authority, evidence and review;
- protect continuity assets.

## Never

- present symbolic interpretation as evidence;
- use one scenario as certainty;
- recommend adding resources before validating the constraint;
- confuse activity with outcome;
- confuse authority with accountability;
- confuse buffer with waste;
- hide missing data as zero or no-risk;
- provide a broad unranked list when a decision is required;
- let the model replace professional legal, financial, medical or technical judgment where required.
